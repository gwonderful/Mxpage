## 2. 重要行为变化

### 已有成图时，不能直接整页重新规划

这是防止旧模块和历史版本被级联删除的保守保护。可以继续编辑现有模块、重绘单图；若要全新方案，请新建项目。没有悄悄删除历史，也没有按相似标题猜测新旧图片映射。

旧项目没有 `plannedGenerationRequirements` 时显示“旧规划未记录补充要求版本”。这不表示要求没有生效，不需要仅因这一提示重复调用 AI。

### 批量重试只补缺图

重试创建新任务，原失败/取消记录保持不变。缺图补生成不会重做已有图片。如果模块保留旧图片，但这次重绘失败，请使用该模块的“重生成”入口；批量“补缺图”不会替换它。

### 进程中断后的恢复边界

- 遗留批任务在检查时会安全结束，随后可以补生成缺失模块。
- 独立单图任务不单凭等待时长自动抢占，避免误伤另一进程仍执行的请求。服务中断后，可使用模块的“终止当前头图/详情页”，再重新生成；取消入口能处理持久化的遗留任务。
- 当前仍是进程内后台执行器，没有宣称实现“重启后自动续跑”。外部模型是否已产生结果不确定时，用户重试仍可能产生新的外部计算。
- 取消发生在文件已保存之后，可能保留未激活的资源；不会替换原图。没有删除这些潜在可恢复产物。

### 完整导出不再默默遗漏模块

有规划但缺生成图时，完整导出返回缺失清单，不创建一个冒充完整的 ZIP。无规划的素材导出仍可使用，清单标记为 uploaded_asset。两个图片子目录即使被合并，也不会因头图/详情图编号相同而覆盖。

## 4. 没有实施或没有验证的事项

本轮修复确定性错误以及由竞态、重复请求、错误重试造成的浪费；**不等于完成了审计报告所有性能实验建议**。

- 没有改为多图并发、删除 Prompt Agent、降低推理强度、改模型、缩短图片超时或启用 SVG 来掩盖失败。
- 没有实现持久队列、跨重启自动续跑或跨项目账号级并发调度。
- 没有新增请求级 token/图片额度遥测；真实 token 仍不能从字符数精确计算。
- 未进行真实模型 10 图 A/B，因此不能声称出图时间降低多少、token 节省多少或服务永不失败。外部额度、网络、限流仍可能导致失败，但本次覆盖的错误状态与恢复路径已获得回归保护。
- 用户所说“十张只有六张”的历史事件仍按要求暂不定位；导出同名风险修复不是对那次历史事故原因的断言。

后续如要追求实测提速与省量，先补请求级阶段/用量记录，再对 Prompt Agent 按需启用、减少重复附图与受限并发逐项做质量对照，避免在没有数据时牺牲成图质量。
